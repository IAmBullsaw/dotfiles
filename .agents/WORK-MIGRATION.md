# Work machine migration: `~/.agents.local` → `~/dotwork/.agents`, generated `~/.agents`

Runbook for the AI agent on the work machine. Written 2026-10-30 on the home machine, where this migration is already done. Read the whole file before running anything.

## 0. Rules for the agent running this

- Work phase by phase. Each phase ends with a **STOP**: report what you found in the format given and wait for the user before the next phase.
- Phase A is read-only. Nothing is changed until the user has seen the inventory.
- Never delete anything. Copy, don't move. Old locations stay in place until the user approves removing them (Phase I).
- Never put work content (employer names, internal hosts, ticket IDs, team names, internal URLs, work process) into `~/dotfiles`. Work content goes only in `~/dotwork`.
- Commit only when the user asks. Never push without explicit confirmation, in either repo.
- Verify before claiming: run the command, show the output. If something differs from what this file expects, stop and report it instead of improvising.
- Use `rg`, not `grep`. Never run `git clean`.

## 1. What changed and where it ends up

Before (set up 2026-10-26):
- `~/.agents` was a symlink to `~/dotfiles/agents` (personal content).
- `~/.agents.local/` held work skills, the work `AGENTS.md`, Kiro agents/hooks and `agents-sync/leak-patterns.txt`.
- Kiro's main agent listed skills from two globs (`~/.agents/skills` and `~/.agents.local/skills`), so a skill name in both was an error (Kiro lists both copies).

Now (home machine, dotfiles commit `b2eeb0f`):
- The personal source is `~/dotfiles/.agents/` (folder renamed from `agents/`).
- The work source is `~/dotwork/.agents/`, a separate repo on employer git (replaces `~/.agents.local`).
- `~/.agents/` is a **generated real folder** built by `agents-sync`:
  - `AGENTS.md` → personal `AGENTS.md`
  - `AGENTS.work.md` → work `AGENTS.md`
  - `skills/<name>` → the winning skill folder. When a name exists in both repos, the work folder replaces the personal one as a whole, and the plan prints an `override` line.
- Kiro agents and hooks: `targets/kiro/{agents,hooks}/*` from both repos are linked into `~/.kiro/`, with work winning per file name.
- Claude Code (only if `~/.claude` exists): skill links plus a generated `~/.claude/CLAUDE.md` stub.
- Kiro's main agent references only `~/.agents`: `file://~/.agents/AGENTS.md`, `file://~/.agents/AGENTS.work.md`, and one `skill://~/.agents/skills/*/SKILL.md`.

End state on this machine:
```
~/dotfiles/.agents/   personal (git, personal remote)
~/dotwork/.agents/    work (git, employer remote)
~/.agents/            generated by agents-sync, never edited
~/.kiro/agents|hooks  links into the two repos (recorded in agents-sync's manifest)
~/.kiro/agents/<main> references ~/.agents only
```

## Phase F: migrate

```bash
$agents --work ~/dotwork/.agents sync --dry-run
```

Expected actions:

| Action | Path | Meaning |
|---|---|---|
| `conflict:in-the-way` | `~/.agents` | the old link; `--adopt` backs it up and builds the real folder |
| `create` | `~/.agents/skills/...`, `~/.agents/AGENTS.md`, `~/.agents/AGENTS.work.md` | the view |
| `relink` | `~/.kiro/agents/*`, `~/.kiro/hooks/*` | manifest entries pointing at old paths, now pointing into the repos |
| `conflict:real-file` | `~/.kiro/agents/<x>.json` | a real file agents-sync didn't create, e.g. a main agent edited in place. **Show it to the user.** `--adopt` backs it up and links the repo version instead, so the repo version must contain everything |
| `conflict:foreign-link` | `~/.kiro/...` | a link agents-sync didn't create (e.g. made by hand to `~/.agents.local`). Never adopted. Ask the user; once removed by them, sync creates it |
| `conflict:real-file` / `adopt` | `~/.claude/CLAUDE.md` | only if Claude Code is used here; the hand-written file is backed up and replaced by the stub. Ask first |
| `conflict:inside-source-repo` | anything | a tool home links into a repo. **Stop**, report |
| `override` lines | skills, kiro files | expected, already confirmed in Phase D |

## Rollback

1. `$agents --work ~/dotwork/.agents unlink`. This removes everything agents-sync made and restores backups, including the old `~/.agents` link and any adopted file.
2. The restored `~/.agents` link points at `~/dotfiles/agents`, which no longer exists. To fully return to the old setup, check out dotfiles at `f65e881` (before the rename), or relink `~/.agents` to `~/dotfiles/.agents` by hand.
3. `~/.agents.local` was never touched, so the old Kiro agents work again once `~/.agents` resolves.
