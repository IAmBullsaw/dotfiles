# agents

One place for everything I teach my AI coding tools: instructions, skills and agent configs. Personal defaults live here, work additions and overrides live in a separate work repo, and `agents-sync` merges both into `~/.agents` and wires that into each tool. It works with Kiro CLI (work) and Claude Code (home) today, and Codex reads `~/.agents/skills` natively.

Each tool keeps its own home (`~/.kiro`, `~/.claude`, …). Nothing is redirected: no `KIRO_HOME`, no wrapper scripts, no symlinked tool homes. Tools run exactly as installed.

## Idea in three lines

1. **Write once, in open formats.** `AGENTS.md` for always-on instructions, [Agent Skills](https://agentskills.io) (`SKILL.md`) for workflows. Tool-only formats (agents, hooks, MCP) stay native.
2. **Point, don't copy.** Each tool gets content through the lightest thing that works: native discovery, then a config reference, then a per-item symlink, then a generated stub. Never a copy of a skill.
3. **Shrink over time.** When a tool starts reading these formats natively, its adapter gets deleted.

## Three places

```
~/dotfiles/.agents/          personal source (this repo, git)
~/dotwork/.agents/           work source (separate repo on employer infra, optional)
~/.agents/                   GENERATED by agents-sync. Never edit it, never commit it.
  AGENTS.md       -> personal AGENTS.md
  AGENTS.work.md  -> work AGENTS.md (only if it exists)
  skills/<name>   -> the winning source's skill folder
```

Skills in `~/.agents/skills` are folder symlinks, so editing through them edits the source repo. Which repo a skill comes from: `readlink ~/.agents/skills/<name>`.

## Layout of a source

```
.agents/
├── AGENTS.md               # always-on rules. Short, hand-written.
├── skills/<name>/          # one folder per skill (Agent Skills standard)
│   ├── SKILL.md            #   name + description (the trigger) + procedure
│   ├── references/         #   long docs, loaded only when needed
│   ├── assets/             #   templates, schemas, data
│   └── scripts/            #   deterministic helpers
├── targets/<tool>/         # tool-specific glue, only for tools I use
│   ├── kiro/
│   │   ├── target.json     #   how each capability reaches Kiro, with test evidence
│   │   ├── agents/*.json   #   Kiro custom agents (native format)
│   │   └── hooks/*         #   Kiro hook scripts
│   └── claude/
│       └── target.json     #   Claude skill exclude list, with test evidence
├── bin/agents-sync         # personal repo only: the merge + adapters, Python stdlib
└── tests/                  # personal repo only
```

No top-level `agents/`, `workflows/`, `schemas/` or `references/`: no tool discovers them. Workflows are skills, schemas go in a skill's `assets/`, references in a skill's `references/`, agent definitions in `targets/<tool>/agents/`. Add a folder when a real file needs it.

## Merge rules (personal + work)

| Item | Identity | Same identity in both |
|---|---|---|
| Skill | folder name, which must equal frontmatter `name` | Work replaces the **whole folder**. The plan prints `override skills/<name>: work replaces personal` |
| `AGENTS.md` | n/a | **Layered, not overridden.** Both load, personal first, then work (`AGENTS.work.md`) |
| Kiro agent / hook | file name | Work replaces the whole file, plan prints an override line |
| MCP servers | n/a | **Never merged or generated.** Each repo keeps its servers in the tool's native config, secrets only as `${VAR}` references, personal servers never in work agents |

Both sources are read-only to `agents-sync`. It refuses to write anything that resolves inside a source repo.

## How content reaches each tool

| Tool | Instructions | Skills | Other |
|---|---|---|---|
| Claude Code | Generated `~/.claude/CLAUDE.md` stub: `@~/.agents/AGENTS.md` (+ `AGENTS.work.md`) | `~/.claude/skills/<name>` → `~/.agents/skills/<name>`, minus `targets/claude/target.json` excludes | Subagents, hooks, MCP: native, not managed yet |
| Kiro CLI | Custom agent resources `file://~/.agents/AGENTS.md`, `file://~/.agents/AGENTS.work.md` | One resource glob `skill://~/.agents/skills/*/SKILL.md` | `targets/kiro/{agents,hooks}/*` linked into `~/.kiro/`; MCP native |
| Codex | (not set up) | Reads `~/.agents/skills` natively | |

Precedence inside each tool stays native and applies to project scope only: Claude ranks a global skill above a project skill with the same name (hence the `healthcheck` exclude), Kiro ranks workspace over global. `agents-sync` only decides personal vs work.

## Day to day

```bash
nvim ~/dotfiles/.agents/skills/my-skill/SKILL.md   # write or edit (or through ~/.agents/skills/...)
agents-sync check                                   # validate frontmatter, names, leaks, overrides
agents-sync sync --dry-run                          # see what would change
agents-sync sync                                    # apply: new/removed skills, overrides, stubs
agents-sync status                                  # what it manages and whether anything drifted
agents-sync unlink                                  # remove everything it made, restore backups
```

Paths: `--personal` / `$AGENTS_PERSONAL` (default: the repo `agents-sync` lives in), `--work` / `$AGENTS_WORK` (default `~/dotwork/.agents`, optional).

Editing a skill's content needs no sync. Adding, removing or overriding a skill does.

## Safety

- Everything it creates is recorded in `~/.local/state/agents-sync/manifest.json`. It only repoints or removes what it recorded, and only while it is still exactly what it made.
- Anything else in the way (a real file, a foreign link, an edited generated stub) is a conflict and nothing is applied. `--adopt` moves the thing into `~/.local/state/agents-sync/backups/<time>/` and takes over; `unlink` puts it back.
- Generated files start with `<!-- Generated by agents-sync.`. Edit the source and re-run sync instead.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `conflict:in-the-way ~/.agents` | Old layout: `~/.agents` is a link to the repo. Read the dry run, then `agents-sync sync --adopt` once |
| `conflict:real-file ~/.claude/CLAUDE.md` | Hand-written file. Move anything worth keeping into a source, then `--adopt` |
| `conflict:edited-by-hand` | A generated file was edited. Put the change in the source, then `--adopt` |
| `conflict:inside-source-repo` | A tool home (or `~/.agents`) links into a source repo. Fix the link by hand |
| Skill missing in a tool | `agents-sync status`; for Claude check the exclude list; for Kiro check the agent's `skill://` glob |
| Same skill twice in Kiro/Codex | Something still points at a source repo directly instead of `~/.agents` |

## Adding a new CLI

1. Find out, from its docs and a quick test, where it reads instructions and skills, and whether it follows symlinks. Record the result in `targets/<tool>/target.json` with a dated evidence entry.
2. If it reads `~/.agents/skills` or `AGENTS.md` natively, stop: nothing to build.
3. Otherwise add its items in `desired()` in `bin/agents-sync`: links into its home pointing at `~/.agents/...`, or a generated stub when it needs its own file. Only when its home directory exists.
4. Add tests in `tests/test_agents_sync_sync.py` (links, excludes, rerun, no home → nothing created).
5. Add a row to the table above.

## New machine

Ansible (`ansible/agents.yml`) links `agents-sync` into `~/.local/bin`, runs `check` and `sync --dry-run`, and applies only with `agents_sync_apply=true`. It never passes `--adopt` and never creates tool links itself.

```bash
ansible-playbook setup.yml --tags agents                                      # plan only
ansible-playbook setup.yml --tags agents -e agents_sync_apply=true
ansible-playbook setup.yml --tags agents -e agents_work_dir=~/dot-ai/.agents  # work repo elsewhere
```

## Never

- Set `KIRO_HOME`, `CLAUDE_CONFIG_DIR` or similar.
- Wrap a CLI in a PATH shim, or symlink a whole tool home.
- Edit anything under `~/.agents` that isn't a skill (skills edit the source through their link).
- Put secrets or work content in this repo. Work content goes in the work repo.
